# TASK-015

## Summary
가짜 분석기를 사용해 사람이 입력한 테스트 실행 로그를 분석 결과로 돌려주는 독립 Python/FastAPI 서비스의 1단계 API와 테스트를 완성한다.

## Background
테스트 실행 로그를 사람이 직접 읽고 실패 원인을 좁히는 데 시간이 든다.
ADR-007은 로그를 입력받아 원인 후보, 로그에 실제 존재하는 근거, 다음 확인 사항을 돌려주는 독립 Python/FastAPI 서비스를 `services/log-analyzer/`에 두기로 결정했다.

ADR-007 3.5에 따라 실제 AI 모델을 연결하기 전에, 가짜 분석기로 API의 요청·응답과 오류 처리 흐름을 먼저 확정한다.
이렇게 하면 외부 응답과 무관하게 계약과 오류 처리를 결정적으로 검증할 수 있고, 2단계에서는 분석기만 실제 AI로 바꾸게 된다.

GitHub Issue: #15

## Goals
- ADR-007이 정한 위치에 독립 실행되는 Python/FastAPI 서비스의 기반을 마련한다
- 사람이 수동으로 입력한 테스트 실행 로그를 받아 분석 결과를 돌려준다
- 가짜 분석기로 정상, 잘못된 입력, 분석기 오류, 타임아웃의 처리 흐름을 결정적으로 검증한다
- 2단계에서 실제 AI 모델로 분석기를 교체할 수 있는 상태로 남긴다

## Scope

### In Scope
- 테스트 실행 로그를 입력받아 분석 결과를 반환하는 API
- 분석 결과의 구성: 원인 후보, 각 원인 후보의 근거, 다음 확인 사항
- 결정적으로 동작하는 가짜 분석기 (정상 결과, 분석기 오류, 타임아웃을 재현)
- 잘못된 입력, 분석기 오류, 타임아웃에 대한 오류 응답
- 직접 만든 테스트 로그를 사용하는 자동화 테스트
- `services/log-analyzer/` 안의 서비스 의존성 정의와 고정 (`pyproject.toml`, `uv.lock`)

### Out of Scope
- 실제 AI 모델 연결과 그 확인 테스트 (2단계 목표)
- Spring 애플리케이션과의 연동
- 배포
- 이 서비스를 실행하거나 테스트하는 GitHub Actions 워크플로
- `src/`, `.github/`, 기존 Spring·루트 빌드 구성(`build.gradle`, `settings.gradle`, Gradle wrapper 등)의 변경
- 분석 요청이나 결과의 저장
- 인증과 권한

## Requirements

### Functional
- 사용자는 테스트 실행 로그를 텍스트로 입력해 분석을 요청할 수 있다
- 분석이 성공하면 응답은 원인 후보, 각 원인 후보의 근거, 다음 확인 사항을 포함한다
- 성공 응답에 포함되는 근거는 입력한 로그에서 실제로 존재함이 검증된 내용이어야 한다
- 입력 로그에서 검증되지 않은 근거는 성공 응답에 포함하지 않는다. 이 경우 요청을 실패로 처리할지, 해당 항목을 제외하고 응답할지는 DESIGN에서 정한다
- 로그가 없거나 비어 있거나 DESIGN에서 정한 크기 제한을 넘는 등 잘못된 입력은 분석기를 호출하지 않고 클라이언트 오류로 거절한다
- 분석기가 실패하면 서비스는 분석기 오류임을 알 수 있는 오류 응답을 돌려준다
- 분석이 DESIGN에서 정한 시간 안에 끝나지 않으면 서비스는 타임아웃임을 알 수 있는 오류 응답을 돌려준다
- 잘못된 입력, 분석기 오류, 타임아웃은 서로 구분되는 오류 응답을 가진다
- 분석기는 이 단계에서 가짜 분석기만 사용하며, 정상 결과, 분석기 오류, 타임아웃을 각각 결정적으로 재현할 수 있다

### Non-Functional
- 기술 스택과 위치는 ADR-007을 따른다 (Python 3.12, FastAPI, Pydantic v2, pytest, uv, `services/log-analyzer/`)
- 서비스는 Spring 애플리케이션과 코드, 빌드, 실행 단위를 공유하지 않는다
- 서비스는 분석 요청과 결과를 저장하지 않는다 (stateless)
- 자동화 테스트는 외부 서비스, 실제 AI, secret, 네트워크 없이 실행된다
- 타임아웃 테스트는 실제로 오래 기다리지 않고 짧은 시간 안에 끝난다
- 오류 응답은 스택 트레이스, 내부 경로, secret을 노출하지 않는다
- 의존성은 `services/log-analyzer/`의 `pyproject.toml`에 정의하고 `uv.lock`으로 버전을 고정한다

## Acceptance Criteria
- [ ] 직접 만든 실패 로그로 분석을 요청하면 성공 상태 코드와 함께 원인 후보, 근거, 다음 확인 사항이 모두 포함된 응답을 받는다
- [ ] 성공 응답의 모든 근거가 요청한 로그 안에 그대로 존재함을 자동화 테스트로 확인한다
- [ ] 가짜 분석기가 입력 로그에 없는 근거를 돌려주는 경우, 검증되지 않은 근거가 성공 응답에 포함되지 않고 DESIGN에서 정한 방식(실패 처리 또는 항목 제외)대로 처리됨을 자동화 테스트로 확인한다
- [ ] 로그가 없는 요청, 비어 있는 로그, 크기 제한을 넘는 로그는 각각 DESIGN에서 정한 4xx 상태 코드로 거절되고, 분석기가 호출되지 않음을 자동화 테스트로 확인한다
- [ ] 가짜 분석기가 오류를 내면 DESIGN에서 정한 분석기 오류 상태 코드와 오류 응답을 받는다
- [ ] 가짜 분석기가 정해진 시간 안에 끝나지 않으면 DESIGN에서 정한 타임아웃 상태 코드와 오류 응답을 받는다
- [ ] 잘못된 입력, 분석기 오류, 타임아웃의 오류 응답이 서로 구분되며, 어느 오류 응답에도 스택 트레이스나 내부 경로가 포함되지 않는다
- [ ] 자동화 테스트 전체가 네트워크와 secret 없이 통과한다
- [ ] 타임아웃 테스트를 포함한 자동화 테스트 전체가 DESIGN에서 정한 시간 안에 끝난다
- [ ] 변경 파일이 `services/log-analyzer/` 아래로 한정되며, `src/`, `.github/`, 기존 Spring·루트 빌드 구성은 변경되지 않는다 (서비스의 `pyproject.toml`과 `uv.lock`은 `services/log-analyzer/` 안에서 허용)

## Dependencies
- ADR-007 (Accepted, develop `8b54227`)
- 실행 환경: 소유자 Mac에서 Python 3.12와 uv의 설치·실행 가능 여부가 확인되어야 한다 (ADR-007 8. Notes에 미확인으로 기록됨)

## Test Requirements
- 모든 자동화 테스트는 pytest로 실행하며 외부 서비스, 실제 AI, secret, 네트워크를 사용하지 않는다
- API 테스트는 FastAPI의 로컬 테스트 클라이언트로 요청과 응답을 검증한다
- 단위 테스트는 대상(입력 검증, 근거 검증, 가짜 분석기 등)에 맞는 방식으로 작성하며, 테스트 클라이언트 사용을 강제하지 않는다
- 정상 응답 테스트: 직접 만든 실패 로그 1개 이상으로 상태 코드와 응답 본문의 원인 후보, 근거, 다음 확인 사항을 검증한다
- 근거 검증 테스트: 응답의 근거가 입력 로그에 존재하는 경우와, 가짜 분석기가 로그에 없는 근거를 돌려주는 경우를 각각 검증한다. 후자는 DESIGN에서 정한 방식(실패 처리 또는 항목 제외)을 검증한다
- 잘못된 입력 테스트: 로그 없음, 빈 로그, 크기 제한 초과 각각에 대해 상태 코드, 오류 응답 본문, 분석기 미호출을 검증한다
- 분석기 오류 테스트: 가짜 분석기의 실패를 재현해 상태 코드와 오류 응답 본문을 검증한다
- 타임아웃 테스트: 가짜 분석기의 지연을 재현해 상태 코드와 오류 응답 본문을 검증하며, 실제로 오래 기다리지 않는다
- 테스트에 쓰는 로그는 직접 만든 것을 사용한다
- 실제 AI를 호출하는 테스트는 이번 범위에 포함하지 않는다
