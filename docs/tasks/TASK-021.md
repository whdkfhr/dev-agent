# TASK-021

## Summary
AgentRun API가 동시 요청에서도 생성 결과, step log, 상태를 잃지 않고 필수 입력 누락을 400 오류로 거부하도록 고친다.

## Background
TASK-007로 추가된 AgentRun API는 실행 생성, 상태 전이, step log 추가가 모두 현재 값을 읽고 새 값을 만들어 저장하는 방식이라 동시 요청에서 원자성이 보장되지 않는다.
2026-11-22 TASK-007 리뷰(base main 0914fac, reviewed head develop ff28b04)는 이를 데이터 무결성 위험(Critical)으로 판정해 REJECTED했다.
격리 환경에서 200회씩 시도한 결과 같은 실행 ID 중복 생성 성공 29회, step log 유실 186회, 상태 되돌림 22회, 같은 전이 중복 성공 11회가 재현되었다.
또한 실행 ID 누락 시 500이 반환되고, 상태 값이 없는 step log와 Issue 식별자가 없는 실행이 저장되며, 공백 실행 ID가 허용된다.
이 TASK는 Issue #21에 대응한다. TASK-007의 상태를 바꾸지 않고, PR #8의 리뷰 기록을 대신하지 않으며, DESIGN-007을 참조 문서로 유지한다.

## Goals
- 같은 실행 ID로 동시에 생성을 요청해도 정확히 하나만 생성되고 나머지는 중복으로 거부된다.
- 성공 응답을 받은 step log는 동시 요청이 있어도 각각 정확히 한 번씩 남는다.
- 상태 전이와 step log 추가가 동시에 일어나도 성공한 전이와 성공한 로그가 모두 반영된다.
- 본문은 정상적으로 읽혔지만 필수 값이 없거나 비어 있는 요청은 저장되지 않고 입력 오류로 거부된다.
- 위 동작을 회귀 테스트로 고정하고, 수정 전 코드와의 비교 결과를 기록한다.

## Scope

### In Scope
- AgentRun 생성의 중복 방지 원자성
- 같은 AgentRun에 대한 step log 추가의 원자성
- 같은 AgentRun에 대한 상태 전이의 원자성(같은 전이의 동시 요청 포함)
- 상태 전이와 step log 추가가 겹칠 때 서로의 결과를 보존
- 문자열 필수 필드(실행 ID, Issue 식별자, step 이름, tool 이름)의 누락, null, 빈 문자열, 공백 문자열에 대한 400 오류 응답
- enum 필드인 step 상태의 누락, null에 대한 400 오류 응답
- Issue 식별자 필수화에 따른 API 계약 변경과 그 문서화(README의 AgentRun API 설명에 한정)
- 동시성 회귀 테스트, 입력 오류 회귀 테스트, 수정 전 코드와의 비교 실행 기록

### Out of Scope
- 기존 Task, Design, Implementation, Review, PullRequest 서비스의 동시성 처리
- 앱 전체의 요청 본문 변환 실패 처리(깨진 JSON, enum 필드의 빈 문자열·공백·알 수 없는 값, 타입이 맞지 않는 값)와 그 응답 코드 변경
- Issue 제목의 필수화
- 영속 저장소, 분산 락, 다중 인스턴스 간 동기화
- Tool Registry의 실제 도구 실행
- README·architecture의 Tool Registry와 수동 기록 방식 설명 정정(별도 경량 작업)
- TASK-007 상태 변경, DESIGN-007 수정

## Requirements

### Functional
- 같은 실행 ID로 생성 요청이 동시에 여러 건 들어오면 정확히 한 건만 생성 성공 응답을 받고, 나머지는 기존 중복 오류(409)를 받는다. 저장된 실행은 성공 응답을 받은 요청의 값과 같다.
- 같은 실행에 서로 다른 step log 추가 요청이 동시에 여러 건 들어오면, 성공 응답을 받은 요청 각각의 로그가 정확히 한 번씩 저장되고, 성공하지 않은 요청의 로그는 저장되지 않는다.
- 상태 전이와 step log 추가가 동시에 들어오면, 최종 상태는 성공한 전이의 결과이고 성공한 step log는 각각 정확히 한 번씩 남는다.
- 같은 다음 상태로의 전이가 동시에 여러 건 들어오면 정확히 한 건만 성공한다.
- 상태는 기존과 같이 정해진 순서로만 전이되며, 동시 요청으로 이전 상태로 되돌아가지 않는다.
- 생성 요청에서 실행 ID 또는 Issue 식별자가 없거나, null이거나, 빈 문자열이거나, 공백뿐이면 400 입력 오류를 반환하고 저장하지 않는다. Issue 식별자 필수화는 기존에 허용되던 요청을 거부하는 API 계약 변경이다.
- Issue 제목은 기존과 같이 선택 값이다.
- step log 추가 요청에서 step 이름 또는 tool 이름이 없거나, null이거나, 빈 문자열이거나, 공백뿐이면 400 입력 오류를 반환하고 저장하지 않는다.
- step log 추가 요청에서 step 상태 필드가 없거나 null이면 400 입력 오류를 반환하고 저장하지 않는다.
- step 상태에 빈 문자열, 공백, 정의되지 않은 값이 들어온 경우는 요청 본문 변환 실패로 다루며, 이번 작업에서 응답 코드를 바꾸지 않는다. 이 경우에도 저장되지 않아야 한다.
- 등록되지 않은 tool 이름(공백이 아닌 값)에 대한 기존 404 동작은 유지한다.
- 입력 오류 응답은 기존 오류 응답과 같은 형식(code, message)을 따른다.

### Non-Functional
- 기존 인메모리 저장 방식과 레이어드 아키텍처를 유지한다.
- 단일 애플리케이션 인스턴스 안의 동시 요청을 대상으로 한다.
- 운영 의존성을 추가하지 않는다. 테스트 의존성 추가 여부는 DESIGN에서 근거와 함께 정한다.
- 동시성 테스트는 교착 없이 제한 시간 안에 끝나야 한다.
- 스레드 스케줄링에 의존하는 테스트는 수정 전 코드에서 실패가 매번 재현된다고 보장하지 않는다. 수정 전 비교 실행에서 통과가 나와도 문제가 없다는 뜻이 아니며, 이 한계를 결과 기록에 함께 적는다.
- 테스트 주입 지점이나 동시성 검증 전용 도구의 채택은 DESIGN에서 결정한다.
- 다른 API의 동작은 바뀌지 않는다.
- 기존 테스트는 그대로 통과한다. 이번 계약 변경과 직접 충돌하는 기존 테스트가 있으면 DESIGN에서 목록과 사유를 밝힌다.

## Acceptance Criteria
- [ ] 같은 실행 ID로 동시에 생성을 요청하는 테스트에서 성공 응답은 정확히 1건이고 나머지는 409이며, 저장된 실행이 성공한 요청의 값과 같다.
- [ ] 같은 실행에 서로 다른 식별 값을 가진 step log N건을 동시에 추가하는 테스트에서, 성공한 요청의 식별 값 각각이 저장된 step log에 정확히 한 번씩 나타나고 그 밖의 step log는 없다.
- [ ] 상태 전이 1건과 서로 다른 step log 여러 건이 동시에 실행되는 테스트에서 최종 상태가 전이된 상태이고, 성공한 step log 각각이 정확히 한 번씩 남아 있다.
- [ ] 같은 다음 상태로의 전이를 동시에 요청하는 테스트에서 성공은 정확히 1건이다.
- [ ] 위 동시성 테스트를 수정 전 코드(base 커밋)에서도 실행하고, 시도 횟수와 실패 횟수를 스케줄링 의존 한계와 함께 기록한다.
- [ ] 실행 ID 또는 Issue 식별자가 없거나, null이거나, 빈 문자열이거나, 공백뿐인 생성 요청은 400을 반환하고 실행 목록이 바뀌지 않는다.
- [ ] Issue 제목이 없는 생성 요청은 기존과 같이 201을 반환한다.
- [ ] step 이름 또는 tool 이름이 없거나, null이거나, 빈 문자열이거나, 공백뿐인 step log 요청은 400을 반환하고 step log가 추가되지 않는다.
- [ ] step 상태 필드가 없거나 null인 step log 요청은 400을 반환하고 step log가 추가되지 않는다.
- [ ] step 상태에 빈 문자열이나 정의되지 않은 값을 보낸 요청은 step log가 추가되지 않는다(응답 코드는 이번 작업에서 검증하지 않는다).
- [ ] 등록되지 않은 tool 이름의 step log 요청은 기존과 같이 404를 반환한다.
- [ ] 기존 테스트가 모두 통과한다.

## Test Requirements
- 생성, step log 추가, 상태 전이, 전이와 로그의 겹침에 대한 서비스 계층 동시성 회귀 테스트
- 동시성 테스트는 성공한 각 요청의 결과가 정확히 한 번씩 보존되고 성공하지 않은 요청의 결과는 남지 않는다는 불변식을 검증한다
- step log 동시성 테스트는 요청마다 고유한 값을 넣고, 저장 결과에서 각 값이 정확히 한 번씩 나타나는지 검증한다
- 동시성 테스트는 시간 제한을 두고, 수정 전 코드에서의 비교 실행 결과를 기록한다
- 생성과 step log 추가의 필수 값 누락·null·빈 문자열·공백, step 상태 누락·null에 대한 컨트롤러 테스트(400과 오류 형식)
- 입력 오류 요청 후 저장 상태가 바뀌지 않았음을 확인하는 테스트
- Issue 제목 없는 생성의 201, 등록되지 않은 tool의 404 유지 확인
